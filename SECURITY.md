# Security Policy

## Reporting a vulnerability

Please do not disclose exploitable vulnerabilities in a public issue before a fix is available. Use GitHub's private security-reporting path when available; otherwise contact the maintainer privately through the GitHub profile linked to this repository.

When reporting a vulnerability, include the affected component, reproduction steps, expected impact, and any suggested mitigation.

## Sensitive data

This project can work with private voice references, transcripts, books, generated audio, and local library state. Never commit or attach private voice samples, credentials, tokens, personal books, generated private audio, or local application state to public issues, pull requests, or CI artifacts.

## Supported code

Security fixes target the current `main` branch. Historical snapshots and experimental branches may not receive fixes.
